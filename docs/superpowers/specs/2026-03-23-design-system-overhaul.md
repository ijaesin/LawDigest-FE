# 모두의입법 전면 디자인 개선 스펙

## 개요

법안 정보 SNS 서비스 "모두의입법"의 전면 UI/UX 리디자인. 클린 & 미니멀 방향으로 글래스모피즘 기반 디자인 시스템을 Storybook에서 선행 구축하고, 핵심 페이지 순서대로 적용 확장한다.

### 목표

- 현대적인 SNS 웹앱에 걸맞은 비주얼 품질 달성
- 정치적 중립성을 유지하는 컬러 시스템
- 완전한 반응형 디자인 (모바일/태블릿/데스크톱)
- 라이트/다크 모드 완벽 지원
- 재사용 가능한 디자인 시스템 구축

### 접근 방식

**디자인 시스템 선행 구축 (Storybook 기반)**

1. Storybook에서 디자인 토큰 + 공통 컴포넌트를 먼저 구축/문서화
2. 핵심 페이지 순서대로 필요한 컴포넌트를 우선 개발
3. 페이지 적용 시 발견되는 추가 요구사항을 시스템에 피드백
4. 전체 페이지에 순차 확장

### 기술 스택

- Next.js 15 (App Router) / React 19
- Tailwind CSS + CSS 변수 기반 디자인 토큰
- shadcn/ui (커스텀 테마 적용)
- Storybook (컴포넌트 문서화 및 개발)
- CSS 애니메이션/트랜지션 (기본 인터랙션) + `@use-gesture/react` (스와이프/풀투리프레시)
- next-themes (다크 모드)

### 브라우저 지원

- Chrome 105+, Safari 16+, Firefox 110+, Edge 105+
- 컨테이너 쿼리: 전역 지원율 93%+, 미지원 시 미디어 쿼리 폴백

## 1. 컬러 시스템

### 설계 원칙

- **정치적 중립**: 빨강(국민의힘)/파랑(민주당) 계열을 프라이머리에서 배제
- **활기**: 톤 다운이 아닌 생동감 있는 컬러

### 프라이머리: Indigo 계열

## 4. 레이아웃 시스템

### 데스크톱 (lg: 1024px+): 3단 레이아웃

```
┌──────────────────────────────────────────────┐
│ [240px 좌측 네비] [유동 중앙 피드] [300px 우측] │
│                   (max 640px)                 │
│ - 로고            - 메인 콘텐츠    - 검색바     │
│ - 홈              - 피드/상세      - 인기 법안   │
│ - 타임라인                         - 키워드     │
│ - 팔로잉                                       │
│ - 마이페이지                                    │
│ - 검색                                         │
│ - 테마 토글                                     │
└──────────────────────────────────────────────┘
```

- 좌측 네비: 고정(sticky), 글래스 배경, 전체 높이
- 중앙 피드: 스크롤 가능, max-width 640px
- 우측 사이드바: 고정(sticky), 기존 컴포넌트 재배치

**우측 사이드바 페이지별 구성:**

| 페이지                          | 우측 사이드바 콘텐츠                                    |
| ------------------------------- | ------------------------------------------------------- |
| 홈 피드                         | 검색바, 인기 법안 (NotificationTopThree), 트렌딩 키워드 |
| 법안 상세                       | 검색바, 관련 법안 추천, 발의자 요약                     |
| 타임라인                        | 검색바, 회기별 통계 요약                                |
| 의원/정당 상세                  | 검색바, 관련 의원/정당                                  |
| 기타 (팔로잉, 마이페이지, 알림) | 검색바, 인기 법안 (홈과 동일)                           |

### 태블릿 (md: 768px): 2단 레이아웃

```
┌──────────────────────────────┐
│ [72px 아이콘 네비] [유동 피드] │
│                               │
│ 아이콘만 표시     메인 콘텐츠   │
│ 호버 시 툴팁                   │
└──────────────────────────────┘
```

- 좌측 네비: 아이콘만 표시 (72px), 호버 시 라벨 툴팁
- 우측 사이드바: 숨김

### 모바일 (<768px): 단일 컬럼

```
┌─────────────────┐
│ [상단 헤더]      │ ← 스크롤 다운 시 숨김
│                  │
│ [풀 너비 콘텐츠] │
│                  │
│ [하단 네비]      │ ← 글래스모피즘, 스크롤 다운 시 숨김
└─────────────────┘
```

- 상단 헤더: 로고 + 알림 + 테마 토글, 스크롤 반응
- 하단 네비: 홈/타임라인/검색/팔로잉/마이페이지 (5개 아이콘)
- 스와이프 제스처: 좌우 스와이프로 메인 탭 간 전환
- 풀투리프레시: 피드 새로고침
- 스크롤 다운 시 헤더/네비 숨김 → 스크롤 업 시 다시 표시

## 5. 글래스모피즘 컴포넌트 시스템

### 적용 범위 및 레벨

| 컴포넌트      | 글래스 레벨 | 설명                                          |
| ------------- | ----------- | --------------------------------------------- |
| 법안 카드     | `subtle`    | 반투명 배경 + 미세 보더, 호버 시 opacity 증가 |
| 프로필 카드   | `subtle`    | 의원/정당 카드                                |
| 통계 카드     | `subtle`    | 타임라인 통계, 투표 결과                      |
| 좌측 사이드바 | `medium`    | 데스크톱 네비게이션                           |
| 하단 네비     | `medium`    | 모바일 네비게이션 (기존 확장)                 |
| 상단 헤더     | `medium`    | 모바일 스크롤 시 글래스 전환                  |
| 검색 모달     | `heavy`     | 오버레이 + 글래스 배경                        |
| 드롭다운 메뉴 | `heavy`     | 액션 메뉴, 필터 드롭다운                      |
| 배지/태그     | 커스텀      | 반투명 프라이머리/액센트 배경                 |

### 글래스 카드 기본 스타일

```css
.glass-card {
  background: var(--glass-bg-subtle);
  backdrop-filter: var(--glass-blur-subtle);
  border: 1px solid var(--glass-border);
  border-radius: var(--radius-md);
  transition:
    background 200ms ease-out,
    transform 200ms ease-out;
}

.glass-card:hover {
  background: var(--glass-bg-medium);
  transform: translateY(-2px);
}
```

### 글래스 위 텍스트 대비 안전장치

글래스모피즘은 배경에 따라 대비가 불안정할 수 있으므로:

- 텍스트를 포함하는 글래스 요소는 반드시 `--glass-bg-medium` 이상의 opacity를 사용
- 추가로 `text-shadow: 0 0 8px var(--background)` 를 적용하여 가독성 보장
- `prefers-contrast: more` 미디어 쿼리 시 글래스 효과를 비활성화하고 불투명 배경으로 폴백

### 다크 모드에서의 글래스

다크 모드에서 글래스모피즘이 더 돋보이도록:

- 배경에 미세한 그라데이션 노이즈 텍스처 추가
- 보더에 미세한 하이라이트 (top/left에 밝은 라인)
- 카드 간 깊이감을 위한 미세 그림자

## 6. 애니메이션 시스템

### 기본 전환값

| 토큰                | 값                                  | 용도                        |
| ------------------- | ----------------------------------- | --------------------------- |
| `--duration-fast`   | 150ms                               | 호버, 포커스, 토글          |
| `--duration-normal` | 200ms                               | 카드 전환, 탭 전환          |
| `--duration-slow`   | 300ms                               | 모달 열기/닫기, 페이지 전환 |
| `--easing-default`  | `ease-out`                          | 대부분의 전환               |
| `--easing-spring`   | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 바운스 효과 (좋아요 등)     |

### 적용 패턴

| 패턴             | 구현                       | 세부사항                                        |
| ---------------- | -------------------------- | ----------------------------------------------- |
| 카드 호버        | CSS transition             | translateY(-2px) + glass opacity 증가           |
| 페이지 전환      | CSS transition             | 페이드 + 슬라이드 (150ms)                       |
| 탭 전환          | CSS transition             | 언더라인/배경 슬라이드                          |
| 리스트 로딩      | CSS animation              | 순차 페이드인 (stagger 50ms, `animation-delay`) |
| 스크롤 헤더/네비 | CSS transform              | translateY로 show/hide (리페인트 최소화)        |
| 풀투리프레시     | `@use-gesture/react` + CSS | 터치 이벤트 감지 + CSS 트랜지션 피드백          |
| 스와이프 전환    | `@use-gesture/react` + CSS | 좌우 스와이프 감지 + CSS 슬라이드 전환          |

> **라이브러리 선택**: 기본은 CSS 트랜지션/애니메이션만 사용. 터치 제스처(스와이프, 풀투리프레시)에만 `@use-gesture/react` (경량, ~3KB gzip) 추가. Framer Motion은 현재 범위에서 불필요하므로 도입하지 않음.

### 성능 원칙

- `transform`과 `opacity`만 애니메이션 대상
- `will-change`는 활성 애니메이션 요소에만 동적 적용
- `prefers-reduced-motion` 미디어 쿼리로 접근성 지원
- 모바일에서 불필요한 애니메이션 제거 (배터리/성능)

## 8. 반응형 디자인 전략

### 브레이크포인트

| 이름    | 너비           | 레이아웃                     | 네비게이션         |
| ------- | -------------- | ---------------------------- | ------------------ |
| Mobile  | < 768px        | 단일 컬럼                    | 하단 네비 (글래스) |
| Tablet  | 768px - 1023px | 2단 (아이콘 네비 + 피드)     | 좌측 아이콘 네비   |
| Desktop | 1024px+        | 3단 (네비 + 피드 + 사이드바) | 좌측 풀 네비       |

### 반응형 구현 원칙

1. **CSS 변수 기반**: 브레이크포인트별 토큰 값 자동 전환
2. **컨테이너 쿼리**: 카드 등 독립 컴포넌트는 부모 크기에 반응 (미지원 브라우저 시 미디어 쿼리 폴백)
3. **터치 타겟**: 모바일에서 최소 44x44px
4. **콘텐츠 우선**: 모바일에서 장식 요소 제거, 핵심 콘텐츠만
5. **이미지/미디어**: `srcset` 또는 Next.js Image 최적화

### 모바일 전용 인터랙션

`@use-gesture/react` 라이브러리로 터치 이벤트를 감지하고, CSS 트랜지션으로 시각적 피드백을 제공한다.

- **스와이프 제스처**: `useDrag` 훅으로 좌우 스와이프 감지 → CSS transform으로 탭 슬라이드 전환
- **풀투리프레시**: `useDrag` 훅으로 하방 드래그 감지 → 일정 임계값 초과 시 React Query `refetch` 트리거
- **스크롤 반응 네비**: `scroll` 이벤트 리스너 + `requestAnimationFrame`으로 스크롤 방향 감지 → CSS `translateY`로 show/hide
- **스와이프 삭제**: `useDrag` 훅으로 좌측 스와이프 감지 → 삭제 버튼 노출

## 9. 다크 모드 전략

### 구현 방식

- **CSS 변수 전환**: 모든 컬러를 CSS 변수로 관리, `.dark` 클래스에서 값 오버라이드
- **next-themes 유지**: 기존 `ThemeProvider` 활용
- **시스템 연동**: `prefers-color-scheme` 기본 존중, 수동 전환 가능

### 다크 모드 디자인 원칙

1. **순수 블랙 지양**: `#0A0A0A` (Neutral 950) 사용으로 깊이감 유지
2. **글래스 강화**: 다크 모드에서 글래스 효과가 더 돋보이도록 보더 하이라이트 추가
3. **컬러 밝기 조정**: 프라이머리/액센트 컬러를 400 레벨로 올려 가독성 확보
4. **이미지 처리**: CSS `filter: brightness(0.9)` 로 눈부심 방지, 별도 에셋 최소화
5. **그림자 대체**: 다크 모드에서 그림자 대신 보더 하이라이트로 깊이감 표현

### 전환 애니메이션

테마 전환 시 `transition: background-color 200ms, color 200ms` 적용으로 부드러운 전환.

## 13. 상태 패턴 (로딩, 에러, 빈 상태)

### 로딩 상태 (스켈레톤)

모든 데이터 로딩 시 글래스 스켈레톤 사용:

- 글래스 배경(`--glass-bg-subtle`) + 펄스 애니메이션
- 실제 콘텐츠와 동일한 레이아웃 구조 유지
- 카드 스켈레톤: 제목(1줄) + 본문(2줄) + 하단 액션바 형태

```css
.skeleton {
  background: var(--glass-bg-subtle);
  backdrop-filter: var(--glass-blur-subtle);
  border-radius: var(--radius-sm);
  animation: skeleton-pulse 1.5s ease-in-out infinite;
}

@keyframes skeleton-pulse {
  0%,
  100% {
    opacity: 0.4;
  }
  50% {
    opacity: 0.7;
  }
}
```

### 에러 상태

| 유형            | 디자인                             | 액션                   |
| --------------- | ---------------------------------- | ---------------------- |
| 네트워크 에러   | 글래스 카드 + 경고 아이콘 + 메시지 | "다시 시도" 버튼       |
| 404 페이지      | 중앙 정렬 글래스 카드 + 일러스트   | "홈으로 돌아가기" 링크 |
| 서버 에러 (500) | 글래스 카드 + 에러 아이콘          | "다시 시도" 버튼       |
| 인증 만료       | 스낵바 알림 + 자동 리다이렉트      | 로그인 페이지로 이동   |

에러 바운더리는 글래스 카드 내부에 렌더링하며, 페이지 전체가 아닌 해당 섹션만 에러 표시.

## 14. 기술적 고려사항

### 마이그레이션 전략

- 기존 shadcn/ui 컴포넌트의 테마를 CSS 변수로 오버라이드
- 새 글래스 컴포넌트는 기존 컴포넌트와 공존 가능하도록 설계
- 페이지 단위로 새 레이아웃 적용 (라우트별 레이아웃 활용)

### 성능

- 글래스모피즘의 `backdrop-filter`는 GPU 가속 → 과다 중첩 시 성능 저하 주의
- 중첩 글래스 레이어 최대 2단계로 제한
- 저사양 기기 감지 시 글래스 효과 단순화 (`prefers-reduced-transparency`)
- 이미지 최적화: Next.js Image 컴포넌트 활용 지속

### 접근성

- 글래스 배경 위 텍스트 대비율 WCAG AA 이상 유지
- `prefers-reduced-motion` 지원으로 애니메이션 비활성화 옵션
- `prefers-contrast: more` 지원으로 글래스 효과 비활성화 → 불투명 배경 폴백
- `prefers-reduced-transparency` 지원으로 반투명 효과 단순화
- 키보드 네비게이션 전체 지원
- 스크린 리더 호환 시멘틱 마크업 유지
- 포커스 링: 프라이머리 컬러 기반 `focus-visible` 스타일
